TEST_SITE_URLS:   https://www.duolingo.com/

LLM_MODEL:        Claude Opus 5 (claude-opus-5, 2026-09)
AGENT_HARNESS:    Claude Code v2.1.280 (VS Code extension, win32-x64)

ENV_SETUP:        python3 -m pip install -r requirements.txt
                  # PYTHON COMMAND: this manifest writes `python3`, which is
                  # correct on macOS/Linux. On Windows use `py -3` instead
                  # (`python3` is not installed there by default). Every
                  # command below works under either name.
                  # Only `requests` and `beautifulsoup4` are required.
                  # lxml / jsonschema are optional; the audit degrades
                  # honestly without them and still passes validation.
                  # No API key, no network service, no browser needed.

TEST_STEPS:
  1. Unzip the Round 3 submission you already hold
     (brand-ai-readiness-audit.zip) and change into it:

     unzip brand-ai-readiness-audit.zip -d brand-ai-readiness-audit
     cd brand-ai-readiness-audit
     python3 -m pip install -r requirements.txt

     That package IS the engine. Nothing else needs to be fetched: the
     marketplace is self-contained, needs no API key and no network service,
     and the manifest resolves without any external lookup.

  2. Open an agent session in that directory (Claude Code) and give it this
     prompt verbatim:

     Read marketplace.json to find the entrypoint skill, follow its SKILL.md, and audit https://www.duolingo.com/ with --max-pages 10 --no-render, writing to ./audit-run. Then show me the complete report: every finding in priority order with its severity, evidence and suggested fix, and the full mechanism and verification for the most severe one.

     The agent resolves the entrypoint from marketplace.json, reads the
     entrypoint SKILL.md, and runs the command that skill documents:

     python3 skills/audit-orchestrator/scripts/run_audit.py --url https://www.duolingo.com/ --workdir ./audit-run --max-pages 10 --no-render --markdown

  3. The audit writes ./audit-run/audit-report.json (schema-validated) and
     ./audit-run/audit-report.md (human-readable). Findings are sorted by
     severity, then by ascending effort, so the top of the list is the
     prioritized fix order. Per-skill evidence fragments are written to
     ./audit-run/fragments/ and the raw crawl evidence to
     ./audit-run/snapshot.json, so every finding can be traced to what was
     actually fetched.

EXPECTED_OUTPUT:  ./audit-run/audit-report.json
                  # The video shows this same report being produced. Finding
                  # counts move by one or two between runs as the crawler
                  # samples different pages; the severe findings are stable.
